Something very different: Interrupts

A pin edge or a timer can pause your programme and run an interrupt.


from machine import Pin
presses = 0

def on_press(pin):  # the interrupt handler
    global presses
    presses += 1    # an int: no new object

button = Pin(BUTTON_PIN, Pin.IN, Pin.PULL_UP)
# a press pulls the pin low: a falling edge
button.irq(on_press, Pin.IRQ_FALLING)

Not on CircuitPython: use countio, keypad

  • Soft Interruptdefault for pins: queued, so it can lag. May allocate
  • Hard Interrupthard=True: runs at once, heap locked: no floats or append()
  • Hard → softmicropython.schedule(f, arg)
    f runs soft, soon after
  • Be briefyour program waits, no print(), sleep() or filesystem actions

Which lines cost memory?

  • import, def, class
  • a new list, dict, str or bytes
  • s + t, f"{t}", data[4:20]
  • uart.read(64)
  • float maths, even n / 2*
  • if, for, while, try
  • locals, small-int maths: n += 1
  • calling a function or a method
  • reading a pin: pin.value()
  • writing into a buffer: buf[i] = b

   Control flow is free. Each new object takes at least one 16-byte block.

Small tweaks to common habits

packet[4:20]→a memoryview does not copy data
uart.read(64)→uart.readinto(buf) reuses one buffer
magic numbers as globals→const()
1,000 floats in a list→array("f"): ~4 KB, not ~20 KB
 

header = packet[4:20]     # ✕ From a bytearray, copies data
mv = memoryview(packet)   # ✓ create memoryview
header = mv[4:20]         # ✓ view into packet, no copy
      

data = uart.read(64)      # ✕ new bytes object each time
buf = bytearray(64)       # ✓ create once
n = uart.readinto(buf)    # ✓ reuse when reading data
      

REG_ID = 0xD0           # ✕ a global, looked up by name
from micropython import const
_REG_ID = const(0xD0)   # ✓ in the bytecode, no global
      

temps.append(sensor.temperature)  # ✕ ~20 KB of floats
temps = array("f", [0] * 1000)    # ✓ raw floats: ~4 KB
temps[i] = sensor.temperature

Your code lives in RAM too

Compile: the tree becomes bytecode, while the tree is still there.

Then the tree is freed. The bytecode stays.

The import fails on the peak, not on what stays.

Fewer cycles, so make them count


def checksum(buf):
    s = 0
    for b in buf:
        s += b
    return s & 0xFFFF
        

@micropython.native
def checksum(buf):
    s = 0
    for b in buf:
        s += b
    return s & 0xFFFF
        

@micropython.viper
def checksum(buf) -> int:
    p = ptr8(buf)
    s = 0
    for i in range(int(len(buf))):
        s += p[i]
    return s & 0xFFFF

Small tweaks for speed

Time it first, then change only the slow part.

code at module level→inside a function (def main():) code in global space is slow
a method call in a hot loop→toggle = led.toggle save it locally, before the loop
a Python loop over a buffer→Use built-in functions like sum(buf), more efficient
float maths in a fast loop→Use integers with a larger scale (int millivolts instead of float volts)
parsing sensor bytes by hand→struct.unpack_from("<hhh", buf): one call, signs right

Time every call with a decorator

Put @timed above a function, and each call prints how long it took.


import gc, time

def timed(f):
    name = str(f).split()[1]  # portable name
    def wrapper(*args, **kwargs):
        gc.collect()  # no GC mid-timing
        t0 = time.ticks_us()
        result = f(*args, **kwargs)
        dt = time.ticks_diff(time.ticks_us(), t0)
        print(name, dt, "us")
        return result
    return wrapper
  • Time a few calls: the first is often slower.
  • Ticks wrap: use ticks_diff().
  • Not for async: on async def it only times creating the coroutine.
  • CircuitPython: use time.monotonic_ns().
